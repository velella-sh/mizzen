
- **Change history of data.** `mizzen data changes [name]` lists what changed in a collection since its recorded state, and `--write` appends the events to `data-changes/<collection>.jsonl`, an append-only file dated by the data snapshot and never by the clock. `collections.<name>.changelog` (`track`, `ignore`, `labels`, `importThreshold`) chooses the fields and writes each event's summary, a first load is one `imported` event, `--check` fails when data changed without an entry, and `mizzen diff --base` previews the pending entries. See `docs/design/data-changelog.md`.
- **Showing the history.** A history file becomes the read-only collection `<name>.changes`, so lists, filters, grouping, feeds, and search read its events like any collection. A record template repeats its own events with `:::changes` and hands them to the theme as `changes`; `changelog.pages: true` builds `/changes/<name>/`, one page per snapshot date, and `feeds/<name>-changes.xml` whose entry ids are the event ids. `site/data/changelog.md` documents the file, the commands, the block, the pages, and the CI check.
